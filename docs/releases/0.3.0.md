TESK 0.3.0 is the first release of the TESK Helm chart since 0.1.1 (2024), and the first one published from this repository's release workflow: the chart is attached to this release with a GitHub artifact attestation and a Sigstore signature, instead of being added to the Helm repository on `gh-pages`. It deploys [TESK API 1.2.0](https://github.com/elixir-cloud-aai/tesk-api/releases/tag/v1.2.0) and the taskmaster and filer of [tesk-core 0.11.0](https://github.com/elixir-cloud-aai/tesk-core/releases/tag/v0.11.0) by default. The chart now follows Helm's conventions: its objects are named after the release, its values are camelCase and checked by a closed schema, and the API has probes. It adds FTP credentials limited to configured hosts, a timeout for the filer's HTTP(S) requests, a TTL for finished tasks and a maximum queue time, authorisation by a user-info claim, security contexts for the API and the executors, and the Swagger UI off by default. **Existing releases must be installed again**, and several values were renamed: read the [upgrade notes](https://github.com/elixir-cloud-aai/TESK/blob/v0.3.0/docs/upgrading.md#030) first. The commits below list all changes since `v0.2` (2018), the last tag with a `v` prefix, which releases use again from now on (charts 0.1.0 and 0.1.1 were tagged `tesk-0.1.0` and `tesk-0.1.1`), so they include changes released in those charts.

## Breaking changes

- The chart's objects are named after the release (e.g., `<release>-tesk-api`) and selected by the standard `app.kubernetes.io/*` labels, so that several releases can share a namespace; `helm upgrade` from earlier charts fails: install existing releases again (#248, #263)
- Values follow Helm's conventions: camelCase instead of snake_case keys (e.g., `host_name` is `hostName`), `tesk.image` as a map, `ingress.enabled` and `ingress.className` instead of `ingress.rules` and `ingress.ingressClassName`, `transfer.enabled`, `ftp.hostIp`, `auth.envBaseGroup`; old keys fail the installation with their new names (#247, #249, #228, #270)
- `values.schema.json` closes the chart's own maps, so unknown keys (e.g., typos) fail the installation (#228, #270)
- `tesk.securityContext.enabled` is replaced by the maps `tesk.podSecurityContext` and `tesk.securityContext`, with the same defaults (#228, #270)
- The TLS secret template is `tls-secret.yaml-TEMPLATE` (was `tls_secret_name.yml-TEMPLATE`) (#228, #270)
- Default images tesk-api 1.2.0 and taskmaster and filer 0.11.0 (tagged without `v` from now on): the Swagger UI is off unless `tesk.swaggerUi.enabled` is `true`, and the filer sends FTP credentials only to `ftp.hosts`; the filer fails outputs with symbolic links, and the taskmaster and filer tags must be the same release (the installation fails on different releases from 0.11.0 on); see also the upgrade notes of tesk-api and tesk-core (#273, #278)
- With `auth.mode: auth`, tasks created before the upgrade to tesk-api 1.2.0, which records task creators without loss in other labels, no longer belong to their creators; the new value `auth.legacyUserLabels` keeps them theirs for a transition, and the notes warn if it is on with an older tesk-api (#271, #275)
- Charts are released from signed `vX.Y.Z` tags as files attached to GitHub releases; the Helm repository at `https://elixir-cloud-aai.github.io/TESK/` keeps 0.1.0 and 0.1.1 but gets no new versions (#222, #234, #240, #241)
- The service info comes from the values `serviceInfo.*`, and the file `charts/tesk/service-info/service-info.yaml` is removed: move edits of it into values, or into a ConfigMap of your own (`serviceInfo.existingConfigMap`); the defaults describe no deployment, and point `contactUrl` and `documentationUrl` to this repository and its docs (#282, #285)

## Features

- `tesk.taskTtlSeconds` deletes finished tasks after a time, and `tesk.maxQueueSeconds` fails tasks that can't be scheduled in time (#267, #269)
- Authorisation by a claim of the user info, for users without groups (`auth.claim.*`) (#265, #268)
- `tesk.executor.securityContext` runs the executors as non-root users (#264, #266)
- `tesk.keepFailedPvcs` keeps the PVCs of failed and cancelled tasks, which the taskmaster now deletes by default (#261, #262)
- `tesk.filerHttpTimeout` sets the timeout of the filer's HTTP(S) requests (#259, #260)
- `tesk.swaggerUi.enabled` turns the Swagger UI on or off (#243, #245)
- `auth.serviceInfoPublic` controls whether `GET /service-info` needs a token (#216, #217)
- `serviceInfo.*` sets `GET /service-info` when installing a packaged chart; the chart sets `type` and `version` (the tesk-api tag), and the API restarts when the service info changes (#282, #285)

## Security

- `ftp.hosts` limits the hosts that the filer sends the FTP credentials to; deployments with a `.netrc` file (`ftp.netrcSecret`) need no change (#255, #256)
- `auth.clientSecret` is deprecated, as the Swagger UI is a public client; the notes warn if it is set (#257, #258)

## Fixes

- The API's Deployment has startup, readiness and liveness probes, so the Ingress no longer answers `502 Bad Gateway` while the API starts (#253, #254)
- Secret values are quoted, so that values that YAML reads as numbers or booleans keep their form (#250, #251)
- Tasks no longer end in `SYSTEM_ERROR` on Kubernetes 1.31 and later, as the default taskmaster reads all conditions of a job (v0.10.6 and later; chart 0.1.1 deployed v0.10.2) (#218, #220)
- An empty `ingress.className` leaves `ingressClassName` out of the Ingress instead of rendering it as null (#228, #270)
- The Ingress `pathType` is updated (#204)

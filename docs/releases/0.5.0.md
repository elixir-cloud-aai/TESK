TESK 0.5.0 deploys [TESK API 2.1.0](https://github.com/elixir-cloud-aai/tesk-api/releases/tag/v2.1.0) and the taskmaster and filer of [tesk-core 0.13.0](https://github.com/elixir-cloud-aai/tesk-core/releases/tag/v0.13.0) by default, and runs TESK in namespaces that enforce the `restricted` Pod Security Standard or have a quota on `limits.cpu` (e.g., those of the CERIT-SC cluster): new values give the taskmasters', the filers' and the executors' pods security contexts and resources. Each client of `auth.tokenClients` has audiences of its own now, and its tokens are accepted only for them. Releases of chart 0.4.0 are upgraded in place; read the [upgrade notes](https://github.com/elixir-cloud-aai/TESK/blob/v0.5.0/docs/upgrading.md#050) first: with `auth.mode: auth`, users see only their own tasks (the chart can't set tesk-api's task visibility yet), `ram_gb` becomes a hard memory limit, the filers get default resources, values of `auth.tokenClients` must be converted, and `fsGroup` moves from `tesk.executor.securityContext` to `tesk.executor.podSecurityContext`. Upgrade with your values files, not with `--reuse-values`, which keeps the taskmaster and filer of chart 0.4.0.

## Breaking changes

- Default images tesk-api 2.1.0 and taskmaster and filer 0.13.0: with `auth.mode: auth`, users get, list and cancel only their own tasks, super admins and team admins included; executors get their `ram_gb` as a hard memory limit also with `cpu_cores`; the filers request 100m CPU and 128Mi memory and are limited to 1 CPU and 512Mi memory by default (`tesk.filer.resources`); the taskmasters and the executors get default CPU and memory resources (`tesk.taskmaster.resources`, `tesk.executor.defaultCpu`); see also the upgrade notes of tesk-api and tesk-core (#339, #340)
- `auth.tokenClients.clients` is a map from client ID to the client's `audiences` (or `allowAnyAudience`), and the shared `auth.tokenClients.audience` and `auth.tokenClients.allowAnyAudience` are removed: the chart fails with a hint on values of chart 0.4.0, and `auth.tokenClients` needs tesk-api 2.1.0 or later (#336, #338)
- `tesk.executor.securityContext` is the executors' container context, with the fields of a Kubernetes `SecurityContext`; the pod's context is the new `tesk.executor.podSecurityContext`, and the installation fails with a hint while `fsGroup` is under `tesk.executor.securityContext` (#330, #331)

## Features

- Values for namespaces that enforce the `restricted` Pod Security Standard or have a quota on `limits.cpu`: `tesk.taskmaster.podSecurityContext`, `tesk.taskmaster.securityContext`, `tesk.taskmaster.resources`, `tesk.filer.resources`, `tesk.executor.podSecurityContext` and `tesk.executor.defaultCpu`, unset by default; CI installs the chart in such a namespace too (#330, #331)
